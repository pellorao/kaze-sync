# kaze-sync v0.3.1 release notes

[English](RELEASE-NOTES.md) | [简体中文](RELEASE-NOTES.zh-CN.md)

## What this release is

`v0.3.1` (released on 2026-11-15) is a Web UI update to kaze-sync, a self-hosted file sync service with version history for Linux and Windows computers (`kaze-syncd` on OpenWrt or x86-64 Linux with systemd or OpenRC, and `kaze-syncc` clients on Linux and Windows configured centrally in the Web UI). Because text in the Web UI was small, `kaze-syncd` now uses a larger four-step type scale (12, 14, 16, and 20 px), enlarges rows, controls, popovers, and dialogs to match, and adjusts narrow-screen wrapping and table scrolling so pages read comfortably without overflow or clipping. For the full overview of kaze-sync's sync, write-control, and restore features, see the [user manual](docs/manuals/user-manual.md), the [changelog](CHANGELOG.md), or the `v0.1.0` release notes in the Git tag `v0.1.0`.

Like earlier releases, this is a source-only release with no prebuilt binary downloads: build the static binaries from source with Go on any machine as described in [section 2.1 of the user manual](docs/manuals/user-manual.md#21-build-the-binaries). Identify a build with `kaze-syncd --version` and `kaze-syncc --version` (or in the top-left of the Web UI after signing in) and by the Git tag `v0.3.1`.

## Highlights

- **Larger Web UI type scale.** Text across the Web UI was small, so `style.css` now follows the Primer type scale with four CSS variables: `--fs-xs` (12 px), `--fs-sm` (14 px), `--fs-md` (16 px), and `--fs-lg` (20 px). Body text moves from 14 to 16 px with line height 1.6 (was 1.5), text fields move from 14 to 16 px, table text is 16 px (with times and sizes at 14 px), card and dialog titles are 16 px, and the page title stays 20 px. Table headers, tags, counters, help lines, notes, tips, and notification details move from 12 to 14 px, buttons move from 13 to 14 px, and monospace text for paths, rules, and fingerprints is 14 px to match the optical size of 16 px `Source Sans 3`. 12 px is kept only for the version number beside the name, the notification badge, menu group captions, and the end labels of the restore time axis. The fonts themselves do not change, and the server binary size is unchanged in practice.
- **Matching control, row, and dialog sizes.** Everything around the text grew on the existing 2 px spacing grid: table rows are 44 px (40 px in the file list), buttons 32 px high (small 28 px), text fields 40 px, menu items 36 px, tags 24 px, the notification badge 20 px, and switches grew to match, while stand-alone controls (counters, the show-deleted switch, notification links, expanders, and checkboxes) keep at least a 24 px target. Containers widened accordingly: dialogs are 640 px wide (wide 860 px, restore 1000 px, up from 560, 760, and 900 px), the notification list 480 px (was 420 px), the login box 400 px (was 360 px), tips up to 360 px (was 320 px), and the context menu 224 px (was 200 px). The restore time axes (drawn in SVG pixels) and the restore preview height keep their size, and a test (`internal/server/fontsize_test.go`) fails if a font size in `style.css` is not one of the scale variables or if row, control, and dialog sizes fall below the new minimums.
- **Wrapping, table-scroll, and narrow-screen adjustments.** Where a plain enlargement looked wrong, layouts were adjusted to fit: card headers wrap so a long note drops under the title on a narrow screen instead of squeezing Settings page headers into two lines, and table cell padding drops from 12 to 8 px on screens up to 640 px. In the file list, the time zone name in the `Modified` column header no longer breaks in the middle of a word, and size cells (`"16 B"`) do not wrap. The version history dialog keeps each time on one line and scrolls its table sideways inside the dialog on a narrow screen (previously the `Restore` button was cut off and the dialog scrolled as a whole), and the held-changes detail table also scrolls in its own box. In the write-control dialog, the choices and the `Device` label are all 16 px, and two-line status cells on the device page got 4 px vertical padding. Checked with headless Chrome in English, Simplified Chinese, Traditional Chinese, Japanese, and Korean at 400, 800, and 1280 px wide across the overview, folder, device, and settings pages, the dialogs (new folder, add device, confirm, restore, write control, exclusion rules, version history, held changes, and add and edit mapping), the notification list, and the context menu, pages show no horizontal page scroll, overflow, or truncation; one minor pre-existing quirk remains on narrow screens, where wrapping the summary line under a page title can leave a lone `"·"` separator at the start of a line.

## Upgrading

The sync protocol remains at version 6, and database schemas and client behavior are unchanged. No data migration runs during this upgrade; because clients have no Web UI, only the server binary shows the change and clients need no upgrade (though you can still upgrade them in any order; for the full upgrade procedure, see [section 15 of the user manual](docs/manuals/user-manual.md#15-upgrading)):

- **Server (`kaze-syncd`)**: build the `v0.3.1` binary ([manual section 2.1](docs/manuals/user-manual.md#21-build-the-binaries)), copy it to the server, and run `./kaze-syncd install --data <same dir>` as root. Your listening port, TLS certificate, and admin password remain unchanged, and `install` copies the new binary into `<data>/` and restarts the service.
- **Clients (`kaze-syncc`)**: on each Linux or Windows computer, stop the running agent, replace the binary (`kaze-syncc` on Linux; both `kaze-syncc.exe` and the `-H=windowsgui` `kaze-syncc-agent.exe` on Windows), and start the agent again.

## Known limitations

- **Root-only server installation and CA renewal.** Server installation and local CA certificate renewal require root; non-root server deployment is not supported.
- **Source-only, no auto-update.** There are no prebuilt binary downloads and no automatic self-updates.
- **Scope boundaries ([manual section 18](docs/manuals/user-manual.md#18-what-kaze-sync-does-not-do)).** There is no file sharing, multi-user account system, or collaborative editing; no file preview or file download in the Web UI; no syncing of empty directories, Windows directory junctions, file permissions other than the executable bit, file owners, or extended attributes; no end-to-end encryption, transfer compression, or bandwidth rate limiting; no per-device exclusion rules; no two-factor authentication for the Web UI; no desktop tray icons or pop-up notifications on clients; no macOS or mobile clients; no server architectures other than x86-64; and single files larger than 128 GiB are refused by the server.
- **Not a backup.** Historical versions live on the same disk as the server's data; back up the server data directory to another disk or machine ([manual section 14](docs/manuals/user-manual.md#14-backup-and-restore-of-the-server)).
- **Symbolic links on Windows without Developer Mode.** A Windows client without Developer Mode enabled cannot create synced symbolic links locally; the links stay on the server and appear as a single folded warning line per device in the Web UI.
- **High-frequency files.** Files rewritten every few seconds (such as live status or telemetry files) create a new historical version on every write until retention removes them; exclude such paths if that matters ([manual section 7](docs/manuals/user-manual.md#7-exclusion-rules) and [section 13](docs/manuals/user-manual.md#13-retention-and-garbage-collection)).
- **Server storage format.** Server data is stored as deduplicated blocks and SQLite databases rather than plain files; run `kaze-syncd export` as root when you need plain files directly from the server ([manual section 12](docs/manuals/user-manual.md#12-export-to-plain-files)).
- **Server rollback after database migration.** Rolling the server binary back to an older version after a database schema migration requires restoring the pre-upgrade database backup from `<data>/var/backups/` and running `install --new-epoch` ([manual section 15](docs/manuals/user-manual.md#15-upgrading)).
