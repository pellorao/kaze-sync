# kaze-sync 用户手册

[English](user-manual.md) | [简体中文](user-manual.zh-CN.md)

本手册说明 kaze-sync 用户会做的每一项操作: 安装服务端和客户端, 注册设备, 映射文件夹, 编写排除规则, 处理冲突, 恢复旧版本, 备份, 升级, 卸载和排查问题. 假定你会使用终端, `ssh` 和 `scp`. 想用几条命令得到第一个可用的部署, 先看 [README](../../README.zh-CN.md); 本手册用于之后查阅.

两个约定:

- Web UI 有简体中文, 繁体中文, 英文, 日文和韩文五种界面语言 (见第 4 节的设置页); 手册中的按钮, 菜单项和提示都与简体中文界面上的文字一致.
- 在服务端执行的命令标注 `# server`, 在客户端执行的命令标注 `# client`. 把 `<...>` 换成你自己的值.

所有人都一样的部署细节 (给 OpenWrt 只有一块盘的机器分区, systemd 加固, 内存预算的细节) 写在 [`docs/operations.md`](../operations.md), 本手册指向它的章节而不复制.

## 1. 各部分如何配合

- **服务端** (`kaze-syncd`): 一个进程, 保存全部文件及其旧版本, 并提供 Web UI. 运行在 OpenWrt 上, 或使用 systemd 或 OpenRC 的 x86-64 Linux 上 (VPS, 家用服务器).
- **客户端** (`kaze-syncc`): 每台 Linux 或 Windows 电脑上的后台 agent. 它监视本地文件夹, 上传变更, 下载其他设备的变更. 客户端只主动连接服务端, 不需要开放任何端口, 因此在 NAT 之后也能工作.
- **设备**: 已注册的一台电脑, 有一个名称.
- **文件夹**: 服务端上一组有名称的文件, 在所有使用它的设备上内容相同.
- **映射**: 一个文件夹与某台设备上一个本地目录的对应关系. 例如文件夹 `Docs` 在 Windows 笔记本上是 `D:\Docs`, 在 Linux 台式机上是 `/home/me/Docs`. 全部配置 (文件夹, 映射, 规则, 保留期) 都在服务端的 Web UI 中完成, 并推送给客户端, 通常一秒内生效.
- **版本**: 每次覆盖或删除都会在服务端保留旧内容若干天 (默认 30 天), 可以恢复.

Web UI 的全部操作由唯一的管理员完成, 凭一个随机密码登录.

## 2. 安装服务端

### 2.1 构建二进制

没有发布下载, 需要在装有 Go 的机器上从源码构建 (版本见 `go.mod`, 当前为 1.27.3). 构建结果是静态链接的, 没有依赖.

```bash
CGO_ENABLED=0 GOOS=linux   GOARCH=amd64 go build -o kaze-syncd ./cmd/kaze-syncd
CGO_ENABLED=0 GOOS=linux   GOARCH=amd64 go build -o kaze-syncc ./cmd/kaze-syncc
CGO_ENABLED=0 GOOS=windows GOARCH=amd64 go build -o kaze-syncc.exe ./cmd/kaze-syncc
CGO_ENABLED=0 GOOS=windows GOARCH=amd64 go build -ldflags -H=windowsgui -o kaze-syncc-agent.exe ./cmd/kaze-syncc
```

最后一行用同一份源码构建无控制台窗口的版本, Windows 自启动使用它. `kaze-syncc-agent.exe` 必须与 `kaze-syncc.exe` 放在同一目录. 服务端只支持 x86-64.

### 2.2 OpenWrt

前提: 数据盘已挂载, 并且不是根文件系统 (overlay). `install` 拒绝根文件系统上的数据目录: 路由器的闪存很小, 会被写满, 系统升级时数据也会被抹掉. 路由器只有一块盘时, 先在这块盘上新建一个数据分区, 见 [`docs/operations.md`](../operations.md) 的 "OpenWrt 只有一块盘: 新建数据分区" 一节.

把 `kaze-syncd` 复制到路由器上, 然后以 root 执行:

```bash
./kaze-syncd install --data /mnt/data/kaze-sync        # server
/mnt/data/kaze-sync/kaze-syncd admin-password          # server: 只显示一次管理员密码
```

`install` 做的事: 把自己复制到 `<data>/kaze-syncd`; 创建系统用户 `kaze-sync`; 创建并迁移数据库; 生成自签名证书 (带 `--ca` 时生成本地 CA 和由它签发的证书); 在 20000 到 59999 之间随机选一个 TCP 端口 (之后每次执行都保持不变); 写入并启用 `procd` 服务 `/etc/init.d/kaze-sync` 并启动; 把服务文件加入 `/etc/sysupgrade.conf`, 让 `sysupgrade` 保留它们. 它会打印端口和证书指纹 (`sha256:...`). 请记下这两项, 注册客户端时要用.

选项:

| 选项 | 含义 |
|---|---|
| `--data DIR` | 必填. 绝对路径, 只能由字母, 数字和 `. _ - /` 组成 |
| `--listen :PORT` | 指定监听地址, 代替随机端口; 之后的执行沿用 |
| `--cert FILE --key FILE` | 使用自己的证书, 代替自签名证书 (2.4 节) |
| `--ca [--san NAMES]` | 使用本地 CA 和由它签发的证书, 浏览器可以信任它 (2.4 节) |
| `--wan` | 只用于 OpenWrt: 添加名为 `kaze-sync` 的防火墙规则, 允许 WAN 区域访问该端口. 不带 `--wan` 时, 会删除之前留下的这条规则 |
| `--new-epoch` | 只在还原备份之后使用 (第 14 节) |

### 2.3 普通 Linux (systemd 或 OpenRC)

以 root 执行, 数据目录自选 (可以在根文件系统上):

```bash
./kaze-syncd install --data /var/lib/kaze-sync         # server
/var/lib/kaze-sync/kaze-syncd admin-password           # server
```

`install` 自己识别服务管理器 (先 OpenWrt, 再 systemd, 再 OpenRC; 其他一律拒绝). 它创建用户 `kaze-sync` (用 `useradd`, Alpine 上用 busybox `adduser`), 写入服务 (systemd: `/etc/systemd/system/kaze-sync.service`; OpenRC: `/etc/init.d/kaze-sync`), 设为开机启动并启动. 它**不会**配置任何防火墙, 也不接受 `--wan`: 请在云厂商的安全组或本机防火墙中放行打印出的 TCP 端口 (例如 `ufw allow <端口>/tcp` 或 `firewall-cmd --add-port=<端口>/tcp --permanent`).

日常控制:

| | systemd | OpenRC | OpenWrt |
|---|---|---|---|
| 启动, 停止, 重启, 状态 | `systemctl start\|stop\|restart\|status kaze-sync` | `rc-service kaze-sync start\|stop\|restart\|status` | `/etc/init.d/kaze-sync start\|stop\|restart` |
| 日志 | `journalctl -u kaze-sync` | syslog, 标签 `kaze-sync` (Alpine 在 `/var/log/messages`) | `logread` |

服务崩溃后 5 秒自动重启. 开机时数据盘没有挂载的话, 服务会启动失败, 而不是新建一个空库.

systemd 单元带加固选项 (服务只能写 `<data>/var`). 自己的修改请用 drop-in (`systemctl edit kaze-sync`), 不要直接改单元文件, 因为下一次 `install` 会重写它. 细节和 systemd 版本要求见 [`docs/operations.md`](../operations.md) 的 "普通 Linux (systemd 或 OpenRC)" 一节.

`install` 需要 root, 没有受支持的非 root 运行方式.

### 2.4 端口, 证书与防火墙

- **自签名证书 (默认).** 公网和局域网都适用, 有效期 100 年. 客户端按指纹固定证书, 与地址和主机名无关. 浏览器第一次访问时会警告证书, 把它显示的指纹与 `install` 打印的核对后, 接受一次例外.
- **自己的证书.** `--cert /path/fullchain.pem --key /path/key.pem` (绝对路径, 安装时检查). 之后浏览器和客户端按系统根证书校验, 客户端注册时不带 `--fingerprint`. 服务以用户 `kaze-sync` 运行, 启动时自己读取这两个文件, 所以该用户必须能读这两个文件, 并能进入它们上面的每一级目录. `install` 本身以 root 运行, 不检查这一点: 服务用户读不了时, `install` 照常成功, 但服务每次启动都会退出, 日志里是 `permission denied` (服务管理器可能短暂显示为已启动). 例如用 `chgrp kaze-sync key.pem && chmod 640 key.pem` 修复 (对其他人关闭的目录再加 `chgrp kaze-sync <目录> && chmod 750 <目录>`), 然后重启服务. 服务端不监视这些文件: 每次续期后要重启服务 (用 acme.sh 时把重启命令写进 `--reloadcmd`). 之后的 `install` 沿用证书模式, 不能切回自签名. 模式之间切换需要所有客户端重新注册.
- **本地 CA (浏览器信任, 恢复自动填充密码).** `--ca` 让服务端生成自己的证书颁发机构 (CA) 和由它签发的服务端证书. 浏览器对自签名证书显示警告, 也因此不提供填充已保存的密码; 在你的电脑上信任这个 CA 之后, 页面被视为安全, Chrome, Edge 和 Firefox 会重新自动填充密码. 证书覆盖的名称有 `localhost`, `127.0.0.1`, `::1`, 服务器的主机名和 `--listen` 里的主机; 你在浏览器里输入的地址或名称用 `--san` 追加 (逗号分隔, 例如 `--san 192.168.1.1,nas.example.org`, 改列表时重复执行 `install`). 请只用这些名称打开 Web UI, 否则浏览器会再次警告. CA 放在 `<data>/ca/`, 只有 root 能读; 服务本身读不到 CA 私钥. 客户端固定的是 CA 的指纹 (`install` 打印的那个, 注册对话框里也显示它), 所以客户端所在的电脑不需要信任任何东西. 要让浏览器信任这个 CA, 导出它的证书 (不含任何机密), 在每台使用 Web UI 的电脑上导入:

  ```bash
  /mnt/data/kaze-sync/kaze-syncd ca --data /mnt/data/kaze-sync --export ca.pem     # 在服务器上
  ```

  - **Windows (Chrome 和 Edge)**: `certutil -user -addstore Root ca.pem`. Windows 会弹出一次确认安装根证书的对话框, 选 **是**. 证书进入当前用户的存储区, 不需要管理员权限. 重启浏览器.
  - **Linux 系统存储**: `sudo cp ca.pem /usr/local/share/ca-certificates/kaze-sync-ca.crt && sudo update-ca-certificates`. Chrome 和 Chromium 用自己的存储: `certutil -d sql:$HOME/.pki/nssdb -A -t "C,," -n kaze-sync -i ca.pem` (软件包 `libnss3-tools`).
  - **Firefox**: 设置, 隐私与安全, 证书, 查看证书, 证书颁发机构, 导入, 并勾选 "信任由此证书颁发机构来标识网站". (Windows 上的 Firefox 也可以读 Windows 存储: 在 `about:config` 里把 `security.enterprise_roots.enabled` 设为 true.)

  谁拿到 `ca-key.pem`, 谁就能签发你的电脑会信任的证书, 所以请保护好 `<data>/ca/`, 也要把它放进备份 (第 14 节). 服务端证书有效期两年, 剩余不足 90 天时续期: 由 `install`, 由 `kaze-syncd ca --data <data>` (以 root), 或在服务以 CA 私钥属主身份运行时由服务自己完成. 服务运行中会在一分钟内用上续期后的证书, 不需要重启. CA 默认属于 root, 此时请用每月一次的定时任务执行 `kaze-syncd ca --data <data>` (`0 4 1 * * /mnt/data/kaze-sync/kaze-syncd ca --data /mnt/data/kaze-sync`); 忘了的话, 服务在最后 30 天内会在日志里警告. 之后的 `install` 沿用 CA 模式. 从自签名或证书文件模式切换用 `install --ca`; 与其他切换一样, 所有客户端都要重新注册 (对能直接改的客户端, 也可以把 CA 指纹填进它的 `device.json` 的 `fingerprint` 字段并重启).
- **端口.** 默认随机, 避免被扫描到; 用 `--listen :PORT` 指定. 始终是 HTTPS, Web UI 与客户端协议共用它.
- 忘记端口或指纹时, 用同一个 `--data` 再执行一次 `install` (可以重复执行, 会打印这两项), 或在服务端日志里找 `listening` 那一行.

### 2.5 首次登录与管理员密码

用浏览器 (Chrome 或 Edge 114 以上, Firefox 125 以上, Safari 17 以上) 打开 `https://<服务器>:<端口>/`, 用 `admin-password` 打印的密码登录. 登录状态保持 7 天.

`admin-password` 随时可以执行: 它设置新的随机密码, 只显示一次, 并重启服务, 因此所有会话和所有锁定都被清除. 密码不能自己选择. 执行方式是 `<data>/kaze-syncd admin-password`, 或用另一份二进制并加 `--data DIR`.

资源: 服务端正常运行时约占 24 MB 内存; 垃圾回收 (第 13 节) 额外占用的量有上限. 512 MB 内存的机器处理约 512 GB 以内的数据时回收一趟即可完成; 数据更大时只是回收多扫几遍, 内存不会增加.

## 3. 安装并注册客户端

客户端需要 Web UI 给出的注册命令. 在总览页点 **添加设备**, 输入名称 (字母, 数字, `-` 和 `_`, 至多 32 个字符, 不能重复; 名称会出现在冲突副本的文件名中), 再点 **生成注册码**. 对话框显示一次性注册码 (15 分钟有效), 以及可直接复制的 Linux 和 Windows 命令; 服务端使用自签名证书时命令里带指纹:

```text
kaze-syncc enroll https://sync.example.org:41873 K7QF-M2XD-9PLA --fingerprint sha256:...
```

服务端地址是客户端能访问到的名称或 IP 加端口, 必须以 `https://` 开头.

### 3.1 Linux 客户端

把 `kaze-syncc` 复制到一个**固定**位置, 例如 `~/.local/bin/`, 因为自启动项会记录它被执行时的路径. 然后执行对话框里的命令:

```bash
kaze-syncc enroll https://sync.example.org:41873 <CODE> --fingerprint sha256:<HEX>    # client
```

它把设备令牌保存到 `~/.local/state/kaze-sync/`, 写入 systemd 用户单元 `~/.config/systemd/user/kaze-sync.service`, 启用并启动 agent. 用 `systemctl --user status kaze-sync` 检查. Linux 客户端需要 systemd 用户会话, 不支持其他初始化系统. 想让 agent 在你未登录时也运行, 用 `loginctl enable-linger` 开启 linger. `--no-autostart` 只注册, 不设置也不启动服务; 之后用 `kaze-syncc run` 在前台运行 agent.

### 3.2 Windows 客户端

把 `kaze-syncc.exe` 和 `kaze-syncc-agent.exe` 放在同一个固定目录, 在该目录打开终端, 执行对话框里的命令 (`kaze-syncc.exe enroll ...`). 它把令牌保存到 `%LOCALAPPDATA%\kaze-sync\`, 在 `HKCU\Software\Microsoft\Windows\CurrentVersion\Run` 下以名称 `kaze-sync` 注册无窗口的 agent (不需要管理员权限), 并立即启动. 此后每次登录都会自动启动.

### 3.3 注册之后

设备出现在总览页的设备表中, 在线时是绿点. 在你给它映射文件夹 (第 5 节) 之前它不会同步任何东西. 要重新注册一台电脑 (例如重装系统后), 先吊销旧设备, 或者用另一个名称添加新设备, 因为设备名称不能重复; 然后执行新的命令.

## 4. Web UI

每页顶栏有: **kaze-sync** 标志 (回到总览), 通知铃铛 (第 9 节), 齿轮 (设置) 和退出. 页面标题用路径显示当前位置 (`总览 / Docs / projects`).

| 页面 | 地址 | 用途 |
|---|---|---|
| 登录 | `/login` | 管理员密码 |
| 总览 | `/` | 文件夹表和设备表. 按钮: **新建文件夹**, **添加设备** |
| 文件夹 | `/folders/<id>` | 浏览文件, 恢复, 排除规则, 删除文件夹 |
| 设备 | `/devices/<id>` | 该设备的映射, 吊销设备 |
| 设置 | `/settings` | 时区, 语言, 版本保留, 全局排除规则 |

总览的文件夹表显示每个文件夹的状态 (已同步, 同步中并带待传数, 有错误, 未映射, 设备离线), 映射它的设备, 文件数和总大小, 以及错误数和提醒数. 设备表显示系统, 最近连接时间, 该设备上各文件夹的状态, 客户端协议版本 (过旧时红色显示 "N, 过旧", 见第 15 节) 和设备是否已取得最新配置.

页面会自动更新: 变化发生后几秒内 (至多每 5 秒一次), 通知铃铛和总览的表格就会刷新. 文件夹页的文件列表不会自动刷新, 免得大批量同步时反复重新读取; 它会显示 **内容有更新, 刷新**, 而且只在你正在看的这个目录里直接发生了变化 (那里的文件, 或出现或消失的子目录) 时才显示, 子目录深处的变化不触发. **同步中** 只在工作超过约 3 秒时显示; 文件被重写后快速的重新扫描不会让文件夹显示为同步中.

文件列表中, 目录行显示其下所有文件的总大小, 以及其中最近一次修改的时间 (已删除的文件不计入; 只含已删除文件的目录两项都不显示). 这些数字在读取列表时顺手累加, 不增加额外开销.

时间默认按浏览器的时区显示为 `2026-11-03 22:48:27`, 鼠标悬停可看到时区名. 菜单, 对话框和实时更新需要 JavaScript, 页面在手机宽度下也可使用.

**设置页.** **时区**: 跟随浏览器, 或为所有浏览器固定一个 IANA 时区 (列表中每个时区后面是它当前的 UTC 偏移, 如 `+09:00`, 已计入夏令时; 按偏移数值从 `-12:00` 到 `+14:00` 升序排列, 偏移相同的按名称升序); 它只影响 Web UI 显示的时间和你在其中输入的时间. **语言**: 跟随浏览器的语言列表 (默认; 列表里没有可用的语言时用英文), 或固定为五种语言之一; 选择只保存在当前浏览器中, 手机和电脑可以不同, 各语言下的时间都是 `2026-11-03 22:48:27` 的格式. **版本保留**: 旧版本保留的天数, 1 到 3650, 默认 30. **全局排除规则**: 见第 7 节.

## 5. 文件夹与映射

**新建文件夹.** 总览页点 **新建文件夹**, 输入至多 64 字节的名称 (名称不能重复). 新文件夹一开始是空的, 也没有映射.

**映射到设备.** 设备页点 **添加映射**: 选择文件夹 (只列出这台设备上还没有映射的文件夹), 输入本机路径, 并决定是否允许接管非空目录:

- 路径必须是该设备系统下的绝对路径: Windows 上如 `D:\Docs`, Linux 上如 `/home/me/Docs`. 同一台设备的两个映射路径不能互相包含.
- 目录不存在时, 客户端会创建它; 目录存在且为空时, 客户端直接开始同步.
- 目录存在, 非空, 而且从未同步过时, 客户端拒绝同步 (上报 `folder` 错误, 见第 9 节), 除非勾选了 **允许接管非空目录**. 这样可以防止你误把路径填成 `C:\Users\me` 而把它全部上传. 允许接管时, 客户端会把自己的文件与服务端对账: 内容相同的文件直接采纳, 不传输, 这就是从其他同步工具迁移, 或接入另一台已有相同文件的电脑的做法; 内容不同的文件成为冲突副本 (第 8 节).
- 客户端会在目录里放一个标记文件 `.syncroot`. 标记之后消失 (磁盘未挂载, 目录被移走) 时, 客户端停止同步该文件夹并报告错误, 绝不把缺失的目录当作 "全部被删除". 请不要删除 `.syncroot`.

**修改映射.** 在设备页, 行尾的 **⋯** 菜单有 **编辑映射…** 和 **删除映射…**. 修改路径等同于删除旧映射再新增: 旧路径下的文件原样保留, 新路径从头与服务端对账.

**删除映射.** 客户端停止同步该文件夹, 删除它的本地状态库和标记文件. 本地文件原样保留, 文件夹及其历史仍在服务端.

**删除文件夹.** 文件夹页标题行的 **⋯** 菜单, **删除文件夹…**. 只有没有设备映射它时才可用 (先删除映射); 菜单项会注明还有几台设备在映射. 它永久删除文件夹及其全部历史, 它的块在下一次垃圾回收 (第 13 节) 时回收. 客户端上的文件保留.

一台设备上的多个文件夹互相独立: 一个文件夹的长时间上传不会拖慢另一个.

## 6. 设备

**添加**见第 3 节. **在线**指设备当前有一个挂起的长轮询, 或在最近 90 秒内结束过一次. 设备 7 天没有连接会产生提醒 (第 9 节).

**吊销.** 设备页标题行的 **⋯** 菜单, **吊销设备…**. 设备的令牌立即失效, 它的全部映射被删除, 本机文件保留. 被吊销的客户端会记录 `sync is stopped, the server does not accept this device`, 之后大约每十分钟才再试一次. 清理这台电脑见 16.1 节.

## 7. 排除规则

规则决定哪些路径不同步. 规则分两层, 都不属于某台设备:

1. **全局规则**: 设置页的 **全局排除规则**. 对所有设备上的所有文件夹生效. 初始内容是一份默认列表 (见下).
2. **文件夹规则**: 文件夹页, 只在顶层有入口, 即 **排除规则** 按钮 (按钮上显示规则条数). 它们接在全局规则之后.

语法与 `.gitignore` 相同, 每行一条, 匹配的是相对文件夹根的路径, 分隔符一律是 `/`:

- 空行忽略; `#` 开头为注释; `!` 取反; 结尾的 `/` 只匹配目录; 开头或中间含 `/` 的模式相对文件夹根, 否则匹配任意层级.
- `*` 和 `?` 不匹配 `/`; `[a-z]`, `[!a-z]`, `[[:alpha:]]` 是字符类; `**/x`, `x/**`, `a/**/b` 可跨目录匹配.
- 最后一条匹配的规则决定结果. 目录被排除后, 其下内容不能再被重新包含; 想保留被排除目录下的某个文件时, 先重新包含目录, 再排除目录里的内容, 最后重新包含那个文件.
- Windows 设备上匹配不区分大小写, Linux 设备上区分.
- 不支持 `{a,b}`, 也没有逐目录的 `.gitignore` 文件.

示例:

| 规则 | 含义 |
|---|---|
| `node_modules/` | 任意层级名为 `node_modules` 的目录 |
| `/Videos/` | 只排除文件夹根下的 `Videos` 目录 |
| `*.iso` | 所有 `.iso` 文件 |
| `Projects/**/bin/` | `Projects` 下任意深度的 `bin` 目录 |
| `/*` 后接 `!/Docs/` | 只同步根下的 `Docs` 目录 |

文件夹规则不能删除全局规则, 但因为最后匹配的生效, 可以用 `!` 抵消它. 例如全局规则有 `build/` 时, 下面三行让某个文件夹只同步 `build/keep.txt`:

```text
!/build/
/build/*
!/build/keep.txt
```

规则文本框把注释显示为灰色, 无效行显示为红色; 鼠标悬停在红色行上可以看到消息, 全部错误列在文本框下方. 有无效行时保存会被拒绝, 不会改变任何内容.

**内置排除**始终生效, 不能被覆盖: `.syncroot`, 下载中的临时文件 `.syncpart-*` (超过一天没有改动的残留会在下一次扫描时删除), 以及 SQLite 数据库的旁文件 `-wal`, `-shm`, `-journal` (第 10 节).

**默认全局规则**包括: Office 和 Windows 的遗留文件 (`~$*`, `*.tmp`, `Thumbs.db`, `desktop.ini`, `$RECYCLE.BIN/`, `System Volume Information/` 等), 编辑器和锁文件 (`*~`, `.~lock.*`, `.*.sw?`, `*.kate-swp`), 未下载完的文件 (`*.part`, `*.filepart`, `*.crdownload`), macOS 元数据 (`.DS_Store`, `._*`, `.Trashes/` 等), Linux 的遗留文件 (`.Trash-*/`, `.directory`, `.fuse_hidden*`, `.nfs*`), 以及其他同步工具的元数据 (`.stfolder/`, `.stversions/`, `.stignore` 等). 完整列表在设置页. 默认规则只在安装时写入一次, 之后以设置页中的文本为准.

你自己的规则 (`.venv/`, `node_modules/`, 缓存, 每隔几秒就变化一次而会让服务端积累大量版本的文件) 需要自己添加, 默认规则有意不含它们.

**规则变化时的行为.** 新规则在一秒内到达在线的客户端. 新被排除的路径只是不再被跟踪, 本地文件保留; 客户端自己从不因为规则而删除任何东西 (服务端上的副本在保存规则时处理, 见下). 取消排除时, 客户端重新与服务端对账, 差异按和其他冲突一样的方式处理 (第 8 节).

**在 Web UI 中保存规则会删除服务端上命中的文件, 保存前要先预览.** 规则对话框 (以及设置页的全局规则卡片) 只有一个主按钮. 文本与已保存的规则不同且还没有预览时, 按钮是 **预览**. 点击后列出, 并标明 "尚未生效", 服务端已有的文件中被框里的规则命中的那些 (数量和前 10 个路径; 全局规则时带文件夹名), 没有命中时写 "没有命中服务端文件"; 这一步不保存任何东西. 之后按钮变成 **保存**, 有命中文件时变成红色的 **保存并删除 N 个文件**. 预览之后又修改了规则, 预览消失, 按钮回到 **预览**. 点 **保存** 直接保存, 不再另问. 如果预览之后有命中规则的文件上传或消失, 就不保存, 重新显示刷新后的预览并提示 "命中文件有变化, 请再核对", 再点一次按钮即可. 命中的文件随后在服务端按普通删除处理, 进入版本历史, 保留期内可以恢复. 各设备上的本地副本全部保留, 之后不再同步, 离线或还没应用新规则的设备也一样. 之后才开始命中的文件只是不同步, 不会被删除. 没有 JavaScript 时, 有命中文件的保存会先返回预览, 再点红色按钮才保存. **取消** 直接丢弃未保存的修改并关闭, 不再询问; 用其他方式 (如按 Esc) 关闭时, 有未保存的修改会先问是否放弃.

## 8. 冲突与冲突副本

先到服务端者胜. 两台设备在失去联系期间修改了同一个文件时, 后来同步的那台设备这样处理:

| 本设备 | 服务端现状 | 结果 |
|---|---|---|
| 修改 | 修改, 内容相同 | 采纳, 不传输 |
| 修改 | 修改, 内容不同 | 本地文件改名为**冲突副本**并作为新文件上传; 原路径下载服务端版本 |
| 修改 | 已删除 | 修改优先, 重新上传 |
| 删除 | 修改 | 删除让步, 下载服务端的文件 |
| 新建 | 已存在, 内容不同 | 同 "修改, 内容不同" |

不会丢数据: 被覆盖的内容也在版本历史里. 胜负从不取决于各机器的时钟.

冲突副本的命名是在扩展名前插入设备名和本地时间: `report.conflict-laptop-20261101-153012.docx`. 它是普通文件, 会同步到所有设备. 在 Web UI 中, 副本带红色的 **冲突副本** 标签, 原文件带 **有冲突** 标签; 铃铛把冲突列为错误. 在客户端上比较两个文件后, 删除副本 (或改名以同时保留), 通知会自动消失.

其他情形:

- **改名或移动**是删除加新增, 内容相同, 所以其他设备在本地复制而不下载. 一台设备移动目录时, 若另一台设备修改了其中的某个文件, 被修改的文件留在旧位置.
- **大小写.** 服务端在文件夹内不区分大小写. Linux 客户端同时有 `A.txt` 和 `a.txt` 时, 后到的那个被拒绝 (`被拒绝`) 并显示为错误, 请改掉其中一个的名字. 在 Windows 上只改变大小写的改名可以正常同步.
- **Windows 非法名称**在所有设备上都被服务端拒绝: 含 `<>:"\|?*` 或控制字符, 以点或空格结尾, 以及保留名 `CON`, `PRN`, `AUX`, `NUL`, `COM1` 到 `COM9`, `LPT1` 到 `LPT9`. 请在创建它的设备上改名, 或把它排除.
- **文件与目录同名**是冲突: 后到的一方把自己的文件或目录改名为冲突副本名.
- **符号链接**同步链接本身, 从不跟随: 链接目标按写法原样保存为文本 (绝对路径, 相对路径, 悬空链接, 指向文件夹之外的链接都会同步; 目标在别的设备上是否存在由你负责), 不通过链接同步目标的内容. 目标长度超过 4096 字节的链接被跳过 (上报为已跳过). 程序不会通过链接读取或写入任何东西, 所以指向文件夹外目录的链接不会让下载写到文件夹外. 在无法建立链接的设备上 (例如没开启开发人员模式的 Windows), 链接留在服务端, 本机不创建任何东西; 铃铛里每台设备只显示一行折叠的提醒 ("win: 3 个符号链接未建立 (Windows 需开启开发人员模式)"), 文件夹页把这些链接显示为灰色的**未同步**行. 开启开发人员模式 (设置, 系统, 开发者选项) 后链接会自行出现, 不需要重启. 这一行只在受影响的链接集合变化时才变. Windows 联接点不跟随也不同步 (上报为已跳过). 空目录, 可执行位以外的权限, 所有者和扩展属性都不同步. 文件内容按字节原样复制, 不转换行尾.

## 9. 通知

kaze-sync 只在 Web UI 中通知你, 客户端不显示任何通知. 点击铃铛: 图标上有计数 (有错误时为红色, 只有提醒时为黄色, 超过 99 显示 `99+`). 浮窗按文件夹分组; 长期离线的设备归在 **设备** 一组. 每条显示消息, 路径 (链接到文件夹页中的文件, 目标行高亮 2 秒), 设备, 起始时间和处理提示. 同一设备同一种类超过 5 条时折叠成一行, 点击展开.

通知由当前状态算出: 没有需要忽略或清除的东西, 原因消除后通知自动消失. 客户端上报的条目保存在服务端内存中, 所以服务端重启后要等客户端再次上报才重新出现; 冲突副本和长期离线的设备不依赖这一点.

| 来源 | 级别 | 处理 |
|---|---|---|
| 存在冲突副本 | 错误 | 在客户端上比较, 删除副本或改名 |
| `rejected` (被拒绝): 大小写冲突, 非法名称, 文件与目录同名 | 错误 | 在该客户端上改名, 或排除该路径 |
| `io` (读写错误): 其他读写错误 | 错误 | 按消息检查该客户端的磁盘和权限 |
| `folder` (文件夹错误): 同步根缺失, 或非空目录未获准接管 | 错误 | 挂载磁盘, 或在设备页修改路径或勾选接管 |
| `in_use` (占用中): 文件被锁定, 正在写入, 或是打开着的 SQLite 数据库 | 提醒 | 关闭占用它的程序 (第 10 节) |
| `skipped` (已跳过): 本设备无法建立的符号链接 (见第 8 节符号链接一条), 目标超过 4096 字节的链接, Windows 联接点, 不是 UTF-8 的文件名 | 提醒 | 不想看到时用规则排除 |
| 设备 7 天没有连接 | 提醒 | 让设备上线, 或吊销 |

客户端上报为已跳过或被拒绝的条目在服务端并不存在, 所以文件夹页把它们作为灰色的 **未同步** 行列在所在目录里; 行菜单的 **详情** 显示消息, 设备和起始时间. 文件夹页和设备页的标题下还有一行小结 ("1 个错误, 2 个提醒"), 点击打开浮窗.

## 10. 正在使用的文件与 SQLite 数据库

- **Windows.** Word, Outlook 等程序会锁定文件. 读取, 改名或删除文件因为被其他程序打开而失败时, 客户端在 30 秒, 2 分钟, 10 分钟后重试, 之后每次扫描都重试, 并把该文件上报为 `in_use`. 下载期间会保留临时文件. 程序关闭文件后同步自动完成.
- **刚修改的文件.** 文件的修改时间至少超过 5 秒, 并且读取期间没有变化, 才会上传, 所以写到一半的文件不会被上传.
- **SQLite 数据库.** 数据库的旁文件 `<name>-wal` 或 `<name>-journal` 存在且非空时, 视为正在使用: 既不上传, 下载时也不覆盖它, 并上报 `in_use`. 在 WAL 模式下, 这意味着应用关闭数据库后才同步 (或者你先执行 `PRAGMA wal_checkpoint(TRUNCATE)`). 旁文件本身永远不同步. 不要在两台机器上同时使用同一个数据库, 否则会产生冲突副本.
- 虚拟机磁盘镜像只有在虚拟机关机后才能可靠同步. 在 Linux 上无法知道其他程序是否以写方式打开了普通文件, 所以只有上面的 5 秒规则在保护你.

## 11. 恢复旧内容

被覆盖或删除的内容在保留期内都保存着 (第 13 节). Web UI 只显示名称和元数据, 不提供下载; 恢复总是把内容作为当前版本写回, 客户端随后像收到其他变更一样收到它. 恢复从不改写或删除历史.

**单个文件的某个版本.** 在文件夹页打开行菜单 (在行上右键, 点行尾的 **⋯** 按钮, 触屏上长按, 或键盘上按 `Shift+F10`), 选 **版本历史…**. 表格列出每个版本的时间, 大小和产生它的设备, 第一行是当前状态. 在想要的版本上点 **恢复**, 并在该行内确认. 当前内容会进入历史, 所以这次恢复本身也可以撤销.

**已删除的文件.** 打开文件夹页上方的 **显示已删除**. 已删除的文件以灰色显示并带 **已删除** 标签. 菜单有 **恢复最后的内容…**, 也可以打开 **版本历史…** 选择更早的版本.

**文件, 目录或整个文件夹恢复到某一时刻.** 在文件或目录的行菜单中选 **恢复到某一时刻…**; 要恢复当前目录, 用标题行菜单或在空白处右键得到的 **恢复此目录到某一时刻…** (在文件夹顶层, 该项写作 "恢复整个文件夹到某一时刻…"). 在对话框中:

1. 在两条时间轴上选时间, 或直接输入, 格式如 `2026-11-03 22:48:27` (秒可省略). 对话框打开时选的是今天的 "现在". 上面一条是日期轴: 左端是能恢复到的最早时刻 (版本保留期的开始, 或下文的首次导入完成, 取较晚的一个), 右端是 "现在", 蓝色竖线只停在每天的 0 点和两个端点; 拖动它, 或在轴上任意处点一下, 它就跳到最近的那个点. 下面一条是时刻轴, 总是显示你停在的那一天从 0 点到 24 点 (今天也是), 今天 "现在" 之后的部分画成斜线底纹, 不能选. 日期轴上的色带 (用斜条与下轴相连) 标出下轴显示的是哪一段; 在这一段里选时间, 拖动下轴的蓝色竖线或在上面点一下 (精确到分钟, 要精确到秒请直接输入); 拖动下轴不会移动上轴的竖线. 0 点是高刻度, 旁边写日期和星期, 其余是小时刻度 (轴越宽刻度越细, 窄屏上更疏); 基线下面的黄色短线是你选的文件或目录里有改动的各个分钟. 范围的第一天通常不满一天: 最早时刻之前的部分同样画成斜线底纹, 竖线进不去. 时间框随竖线变化, 框上方的文字写明距现在多久. 竖线到 "现在" 之间的淡蓝区域, 就是这次恢复要撤销的部分. 竖线不会吸附到黄色短线上, 但预览针对的是该时刻的状态, 而状态只在黄色短线处改变: 竖线压在短线上或其右侧, 就包含那次改动. `‹` `›` 按钮, 或时刻轴获得焦点时的方向键, 每次走一个改动 (`PageUp`/`PageDown` 走一小时, `Home` 和 `End` 到当天的两端); 日期轴上方向键每次走一天 (`PageUp`/`PageDown` 走七天, `Home` 到最早, `End` 到现在). 输入时间则两条竖线都移到那里. 拖动时只有竖线和文字在动, 松手后才刷新预览 (用键盘和按钮时停一下再刷新), 状态没变就不刷新. 竖线在 "现在", 或在最后一次改动之后时, 没有可比较的内容, 预览会提示先选哪一天, 再选当天的时刻. 预览下方的说明写明所用的时区 (可在设置页改变), 版本保留期和最早可恢复到的时间. 时间早于版本保留期时会提示那时的内容可能已被清理. 时间早于该文件夹的最早记录时, 按文件夹首次导入完成时的状态计算 (首次导入即第一台设备的第一次全量上传, 服务端把第一批文件到达后第一次出现 2 分钟的安静时刻当作它的结束), 对话框写明 "所选时间早于最早记录, 按首次导入完成时的状态计算: 首次导入完成于 <时间>". 首次导入之后才新建的文件在那时不存在, 不会被动 (恢复从不删除文件). 对首次导入之后才新建的目录或文件, 改用它自己的第一条记录, 写明 "所选时间早于最早记录, 按最早记录计算: 最早记录为 <时间>". 预览与恢复结果一致. 完全没有历史记录时会显示 "这里没有任何历史记录".
2. 对话框预览将恢复的内容: 文件数和前 20 个路径, 每个按现在的情况标为 "已删除" 或 "已改变". 预览区的高度固定, 移动竖线时对话框不会跳动. 没有差别时, 按钮保持禁用.
3. 点 **恢复**. 完成后提示条说明恢复了几个文件, 几个失败 (名称冲突, 或文件恰好同时被修改).

对一个路径, 恢复的是该时刻有效的那个版本. 只恢复内容: 该时刻之后新建的文件从不删除, 当前内容会保留在历史中. 这同时覆盖 "误删了整个目录" 和 "一批文件被错误覆盖" 两种情况.

## 12. 导出为普通文件

服务端保存的是块和数据库, 不是普通目录树. 要取出普通文件 (灾难恢复, 迁出), 在服务端以 root 执行 (`var/` 下的数据属于服务用户):

```bash
kaze-syncd export DIR [--data DIR] [--folder NAME|ID] [--at "2026-11-02 12:00[:00]"]     # server
```

不带 `--folder` 时每个文件夹导出到 `DIR/<文件夹名>`; 带 `--folder` 时直接导出到 `DIR`. 不带 `--at` 导出当前状态; 带 `--at` 导出该时刻的状态, 时间按 **UTC** 解释. `--data` 默认是二进制所在的目录. 命令直接读数据库和块, 所以服务停着也能用, 在还原后的备份上也能用. 每个文件写完后都用哈希校验; 缺块或损坏的文件会被报告并跳过, 其余照常导出, 命令以非零状态退出. 文件内容, 可执行位和修改时间都会还原. 请预留足够的磁盘空间: 导出一个文件夹会写出它的全部内容.

## 13. 保留期与垃圾回收

- 每次覆盖或删除都把旧版本保留 `keep_days` 天 (设置页的 **版本保留**, 默认 30, 范围 1 到 3650). 保存新值后立即触发一次清理, 不需要重启.
- 垃圾回收每天一次 (服务启动一分钟后检查, 之后每天一次), 保存保留期后也会立即执行一次. 它先删除超出保留期的版本, 再删除无人引用且超过 1 小时的块, 并清理 `var/tmp/` 中的残留. 它在后台运行, 不影响同步. 已上传但尚未提交的块受 1 小时宽限期保护.
- 因此磁盘空间是在下一次回收之后才减少, 不是在删除的那一刻. 结果记在日志里, 每次一行 (`msg=gc`), 含删除的版本数, 块数, 趟数和耗时; OpenWrt 上用 `logread | grep 'msg=gc '`.
- 一次回收占用的内存上限为 64 MB; 数据特别大时只是需要更多趟. 数据量与内存的对应表在设计文档 (`docs/design.md` 第 7 节).
- 每隔几秒就变化一次的文件每次变化都会产生一个版本. 不值得保留的话, 把它们排除 (第 7 节).

## 14. 服务端的备份与还原

服务端不是备份: 版本与数据在同一块盘上 (不过客户端上有每个文件夹的普通文件副本). 为防止整盘损坏, 请备份 `<data>/var/meta.db`, `<data>/var/folders/`, `<data>/var/blobs/`, 以及很小的 `<data>/var/tls/`, 本地 CA 模式下还有 `<data>/ca/` (没有它们, 还原后的服务端会生成新证书或新 CA, 指纹变化, 所有客户端都要重新注册, 浏览器也要重新信任新 CA). `meta.db` 与各文件夹库必须取自同一时刻, 所以复制它们时要停止服务, 并避开垃圾回收运行的时刻. 块写入后不再改变, 可以在服务运行时复制, 也可以增量复制. 备份放在另一块盘或另一台机器上. 命令如下 (以 systemd 为例, 其他服务管理器换成各自的停止和启动命令):

```bash
systemctl stop kaze-sync                                                          # server
cd /var/lib/kaze-sync/var && tar cf /backup/meta.tar meta.db folders tls
systemctl start kaze-sync                                                         # 停机只有几秒钟
tar cf /backup/blobs.tar blobs
tar cf /backup/ca.tar -C /var/lib/kaze-sync ca                                     # 仅本地 CA 模式
```

**还原** (到新机器, 或原地回滚), 使用同一版本或更新版本的 `kaze-syncd`:

```bash
mkdir -p /var/lib/kaze-sync/var                                                    # server
tar xf /backup/meta.tar  -C /var/lib/kaze-sync/var
tar xf /backup/blobs.tar -C /var/lib/kaze-sync/var
tar xf /backup/ca.tar    -C /var/lib/kaze-sync                                     # 仅本地 CA 模式
./kaze-syncd export /tmp/check --data /var/lib/kaze-sync                           # 可选: 先确认数据可读
./kaze-syncd install --data /var/lib/kaze-sync --new-epoch                         # 修正属主, 更换历史标识, 启动服务
```

任何还原之后都**必须**加 `--new-epoch`. 还原使服务端的历史回到过去; 这个选项让每个客户端放弃它已知的服务端状态, 并从头读取一次. 客户端不需要任何操作. 与备份不同的文件会在客户端上成为冲突副本 (不会丢失), 备份之后在客户端上新增的文件会重新上传, 备份之后在客户端上删除的文件会被取回. 不带该选项时, 客户端只能发现其中一部分回退, 可能悄悄与服务端不一致. 平时升级不要带 `--new-epoch`.

管理员密码, 设备和映射都在 `meta.db` 里: 只要证书也一起还原了, 客户端就不需要重新注册. 不要只还原其中一部分文件.

带 OpenWrt 命令的逐步版本见 [`docs/operations.md`](../operations.md) 的 "备份与还原" 一节.

## 15. 升级

始终先升级**服务端**, 再升级客户端.

1. 构建新的二进制 (2.1 节).
2. **服务端**: 用新二进制执行 `./kaze-syncd install --data <同一个目录>` (在 OpenWrt 或 Linux 上, 以 root). 端口, 证书和密码不变. 它复制新二进制并重启服务 (数据库会自动迁移, 见下文); systemd 下还会重新加载单元定义, 并且会重写单元文件, 所以自己的改动要放在 drop-in 里. OpenWrt 自身的 `sysupgrade` 不影响数据和服务.
3. **Linux 客户端**: 停止 agent, 在原路径替换二进制, 再启动:

```bash
systemctl --user stop kaze-sync                    # client
cp kaze-syncc ~/.local/bin/kaze-syncc
systemctl --user start kaze-sync
```

4. **Windows 客户端**: 运行中的 agent 会锁定它的 exe, 所以先停止它 (PowerShell), 复制两个 exe, 再启动 agent:

```powershell
Stop-Process -Name kaze-syncc-agent
Copy-Item kaze-syncc.exe, kaze-syncc-agent.exe <安装目录>
Start-Process "<安装目录>\kaze-syncc-agent.exe" -ArgumentList run
```

**数据库迁移与回滚.** 服务端启动时 (以及执行 `install` 时) 会自动把自己的数据库升到新版本的结构, 先全局库, 再每个文件夹库; 没有要迁移的就什么也不做. 改动某个库之前, 先把它复制到 `<data>/var/backups/` (`meta-v<旧版本>-<UTC 时间>.db`, 或 `folder-<id>-v<旧版本>-<UTC 时间>.db`; 每个库只保留最近 3 份, 删除文件夹时会一并删除它的备份). 备份和数据库一样大, 所以升级时磁盘要有同样大小的空闲空间. 备份或迁移的某一步失败时, 服务端不会启动, 错误信息会指出是哪个库和原因; 该库不被改动, 排除原因 (例如腾出磁盘空间) 后再启动即可. 不用 root 部署的服务端 (用户级服务) 不需要执行 `install`: 替换二进制并重启就行, 不必手工改库. **回滚客户端.** 客户端各文件夹的状态库 (状态目录中的 `folder-*.db`: Linux 是 `~/.local/state/kaze-sync`, Windows 是 `%LOCALAPPDATA%\kaze-sync`) 会随某些升级改变结构. 把客户端二进制换回旧版本之前, 先停止 agent 并复制这些文件, 回滚时和二进制一起还原. 客户端发现状态库是更新版本建立的, 会停止该文件夹的同步, 并把原因显示在该文件夹的错误里, 而不是每次扫描都失败.

迁移之后想回到旧版本: 停止服务端, 换回旧二进制, 把每个已迁移的库的备份 (取升级时产生的最新一份) 复制回 `var/meta.db` 和 `var/folders/<id>.db` (并删除各库旁边的 `-wal` 和 `-shm` 文件), 再按第 14 节的还原步骤操作, 包括 `--new-epoch`. 旧二进制遇到已被新版本迁移过的库会拒绝启动并说明原因, 不会损坏它.

顺序为什么重要: 有些版本会改变协议 (当前协议版本是 5; 版本 5 加入符号链接, 最低版本也是 5, 所以服务端升级后每个客户端都必须升级). 新客户端对旧服务端发出的成批下载会失败. 比服务端要求的最低版本更旧的客户端会被拒绝 (HTTP 426); 它的日志里大约每分钟出现一条 `client too old, sync is stopped until kaze-syncc is upgraded`, 设备表中该设备显示红色的 "N, 过旧". 按上面的步骤升级这台客户端即可, 数据不受影响, 升级后自动继续同步. 只有让旧客户端无法使用的改动才会提高最低版本, 所以多数升级不强制客户端升级.

## 16. 卸载

### 16.1 客户端

第一步在 Web UI 里做, 让服务端忘掉这台设备, 然后清理电脑. 任何情况下已同步的文件都保留.

1. Web UI: 设备页 **吊销设备…** (如果想保留设备, 只删除映射也可以).
2. Linux: `systemctl --user disable --now kaze-sync`, 删除 `~/.config/systemd/user/kaze-sync.service` (然后 `systemctl --user daemon-reload`), 删除状态目录 `~/.local/state/kaze-sync` (含令牌, 日志和同步状态), 删除二进制.
3. Windows: 结束 `kaze-syncc-agent.exe` (`Stop-Process -Name kaze-syncc-agent`), 删除 `HKCU\Software\Microsoft\Windows\CurrentVersion\Run` 下的值 `kaze-sync`, 删除 `%LOCALAPPDATA%\kaze-sync`, 删除 exe 文件.
4. 可选: 之后可以删除同步目录里的标记文件 `.syncroot`.

### 16.2 服务端

没有卸载命令. 下面的操作会删除服务端和**全部同步历史**; 拿不准时先备份. 先吊销或卸载客户端 (16.1 节), 否则它们会一直重试.

systemd:

```bash
systemctl disable --now kaze-sync                  # server
rm /etc/systemd/system/kaze-sync.service
systemctl daemon-reload
userdel kaze-sync
rm -r /var/lib/kaze-sync                           # 你传给 --data 的数据目录, 内含全部数据
```

OpenRC (Alpine):

```bash
rc-service kaze-sync stop                          # server
rc-update del kaze-sync default
rm /etc/init.d/kaze-sync
deluser kaze-sync                                  # 同时删除同名组
rm -r /var/lib/kaze-sync                           # 你传给 --data 的数据目录
```

OpenWrt:

```bash
/etc/init.d/kaze-sync stop                         # server
/etc/init.d/kaze-sync disable                      # 删除 /etc/rc.d/S99kaze-sync
rm /etc/init.d/kaze-sync
sed -i '/^\/etc\/init.d\/kaze-sync$/d;/^\/etc\/rc.d\/S99kaze-sync$/d' /etc/sysupgrade.conf
uci -q delete firewall.kaze_sync; uci commit firewall; /etc/init.d/firewall reload   # --wan 添加的规则; 没有也无妨
rm -r /mnt/data/kaze-sync                          # 你传给 --data 的数据目录, 内含全部数据
```

数据目录只是数据盘上的一个文件夹, 删除它即释放空间; 磁盘, 分区和挂载项是你自己的, 不会被动. 想把整块盘挪作他用, 请用你惯用的工具卸载并重新分区. OpenWrt 没有 `deluser`: 用户 `kaze-sync` 没有登录 shell, 可以留着; 想删除时执行 `sed -i '/^kaze-sync:/d' /etc/passwd /etc/group /etc/shadow`.

如果你手工在防火墙或安全组里放行过端口, 请把它关掉.

## 17. 排查问题

**日志在哪里.**

| 组件 | 位置 |
|---|---|
| 服务端, systemd | `journalctl -u kaze-sync` |
| 服务端, OpenRC | syslog, 标签 `kaze-sync` (Alpine 在 `/var/log/messages`) |
| 服务端, OpenWrt | `logread` |
| Linux 客户端 | `~/.local/state/kaze-sync/kaze-syncc.log` (设置了 `$XDG_STATE_HOME` 时在 `$XDG_STATE_HOME/kaze-sync/`) |
| Windows 客户端 | `%LOCALAPPDATA%\kaze-sync\kaze-syncc.log` |

客户端日志只记启动, 警告和错误; 超过 10 MB 时立即移到 `kaze-syncc.log.old` (agent 运行中也一样, 只保留一份旧文件).

**客户端的调试时间线.** 要查明某次变更为什么慢, 在客户端的状态目录 (上表所在目录) 里创建一个名为 `debug` 的空文件, 并重启 agent. 日志里就会多出 `level=DEBUG` 行, 记录文件事件, 扫描, 拉取, 以及每个到服务端的请求和耗时. 用完删掉该文件并重启 agent.

**常见提示与问题.**

| 现象 | 原因与处理 |
|---|---|
| `enroll` 提示 `invalid or expired code` | 注册码只能用一次, 有效期 15 分钟. 重新生成一个, 并确认复制完整 |
| `enroll` 提示 `too many failures` (HTTP 429), 或登录页返回 429 | 一小时内失败 10 次会把该 IP 锁定一小时. 等待, 或在服务端执行 `admin-password`, 它重启服务并清除所有锁定 |
| `enroll` 提示 `cannot register device` | 已有同名设备. 先吊销它, 或用另一个名称添加设备 |
| `enroll` 报证书错误 | 指纹不符: 从对话框重新复制命令 (`install` 和日志中的 `listening` 行也有指纹); 或者服务端用的是你自己的证书, 此时必须去掉 `--fingerprint` |
| 浏览器警告证书, 或不自动填充已保存的密码 | 自签名证书的正常现象; 核对指纹后接受一次. 想去掉警告并恢复密码填充, 用本地 CA (2.4 节); 用了它仍警告, 说明这台电脑还没信任该 CA, 或浏览器里的地址不在证书的名称里 (`--san`) |
| 忘记管理员密码, 端口或指纹 | 见 2.5 节和 2.4 节 |
| 服务启动后马上退出, 日志里是证书或私钥的 `permission denied` | 服务用户 `kaze-sync` 读不了你自己的证书文件, 或进不了它们所在的目录 (2.4 节) |
| 重启后服务端没有启动 | 数据盘没有挂载. 服务端此时会退出, 而不是新建一个空库; 挂载磁盘后启动服务 |
| `sync is stopped, the server does not accept this device` | 设备已被吊销. 按新设备重新注册 (3.3 节) |
| `client too old` | 见第 15 节 |
| 某个文件夹有错误, 铃铛里有 `folder` 条目 | 见第 5 节: 本地目录缺失, 磁盘没有挂载, 或没有勾选允许接管非空目录 |
| 变更几秒后才出现, 不是立刻 | 正常: 文件事件先收集 2 秒 (文件持续变化时最多等 10 秒), 文件要超过 5 秒, 然后对端通过长轮询得知. 通常延迟 5 到 10 秒 |
| 首次同步很久 | 每个文件都要读取并计算一次哈希. 一次 19000 个文件, 1.6 GiB 的测试用了约 4.5 分钟 |
| 某个文件没有到达 | 看文件夹页是否有灰色的 **未同步** 行, 并看铃铛: 本设备无法建立的符号链接, 非法名称, 大小写冲突, 文件被占用, 或排除规则 |
| 服务端数据增长很快 | 经常变化的文件每次变化都保留一个版本. 把它们排除 (第 7 节), 或缩短保留期 |

## 18. kaze-sync 不做什么

不做分享, 多用户和协作编辑; Web UI 中没有文件预览和下载; 不同步空目录, Windows 联接点, 权限和所有者; 没有端到端加密, 压缩和带宽限速; 没有按设备的规则 (只想在一台设备上同步的部分, 拆成单独的文件夹); 没有双因素登录; 客户端上没有通知; 没有 macOS 和移动端客户端; 没有自动更新; 服务端只支持 x86-64; 单个超过 128 GiB 的文件服务端会拒收 (一个文件的块列表要整个放在服务端内存中). 原因见 `docs/design.md`.
